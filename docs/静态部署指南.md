# 静态部署指南

站点使用 Next.js 静态导出，部署目录为 `out/`。发布包中的 `site/` 对应网站根目录；`manifest.json` 记录每个文件的 SHA-256，压缩包旁提供整体校验文件。压缩包生成成功只表示本地产物准备完毕。

## 构建与检查

使用 Node.js 22 和 Python 3：

```sh
npm ci
npm test
npm run test:dom
SITE_URL=https://你的真实域名 npm run build
npm run check:export
python3 scripts/package-static.py
```

`SITE_URL` 必须是公开 HTTPS 根地址，不含路径、查询和凭证。它在构建时统一控制 sitemap、robots 和 metadataBase。未设置时使用 `data/site.json` 的 `origin`；默认预留域名不代表已经发布。更换域名后重新构建，不要直接替换生成文件中的字符串。

## 部署

把 `out/` 内全部文件，或 ZIP 内 `site/` 的内容上传至静态托管平台。保留 `_next/`、`data/`、各页面目录及 `404.html`。平台需要支持目录的 `index.html`，未知路径应返回真实 404；不要配置所有地址回退到首页的 SPA 重写。

`_headers` 为支持该约定的平台提供响应头。其他平台需按自身配置方式设置并检查实际 HTTP 响应；不能因为文件存在就认定已经生效。CSP 中保留 `unsafe-inline` 以兼容当前静态 Next.js 脚本和样式，不代表经过完整安全审计。Sites 托管是否采用此文件尚未验证。

发布后检查首页、项目详情、分类、指南、404、筛选分享链接、对比链接、配置复制和提交表单，核对 HTTPS、sitemap 域名及响应头。DOM 测试不验证排版、浏览器兼容性或真实剪贴板权限。CI 包含 Playwright 浏览器测试，但需要远程实际运行后才有通过结论。

`build-info.json` 随构建写入公开域名和内容批次，不含凭证。导出检查使用其中的构建域名核对 sitemap 和 robots，因此打包时不需要再次设置 `SITE_URL`。打包脚本会自动执行导出检查，失败时不生成新包；它不证明源码与旧产物完全一致，源码或域名发生变更后仍必须先重新构建。
